# 今日 · 校园融合助手

> CrossPointX 2026 · Track 2 Reverse Product Innovation · 二组作品

**在线体验：https://today-campus.vercel.app**（手机浏览器打开可"添加到主屏幕"）

**Android 安装包：[today-campus.apk](https://today-campus.vercel.app/download/today-campus.apk)**（1.3 MB，已签名，装好后全屏无地址栏）

把散落在公众号、邮件、班级群和教务系统里的校园信息，压成**一条今天的时间轴**。

学生的问题不是"信息不够"，而是**信息太多、截止太散、时间撞车**。活动发在公众号，课表在教务系统，报名截止在邮件里，作业在群里——每一条都要单独记，记漏就错过。今日做的事很简单：**这一周该做什么，今天就告诉你**。

## 它解决什么

| 现状 | 今日的做法 |
|---|---|
| 活动信息散在 5 个渠道，看完就忘 | 活动库 + 兴趣排序，每条都标清来源和报名截止 |
| 收藏了一堆，到点还是忘报名 | 截止时间直接进今日时间轴，和课表、待办并排 |
| 两个活动撞在同一时段，事后才发现 | 加入今日时立刻算重叠，提前 60 分钟提醒冲突 |
| 通知是长文，懒得读 | 粘贴通知，AI 抽出时间、地点、截止、标签，人工确认后入库 |
| 复习资料靠学长转发，版本混乱 | 资料库按科目归档，标"已核对/待核对"，AI 生成自测题 |

## 五个部分，深浅有别

比赛的 48 小时里我们只把两个部分做深，其余三个做成"能用但浅"的真实入口，不做"建设中"的假页面。

**深（演示主路径）**

1. **今日** — 课表 + 已加入活动 + 报名截止 + 个人待办合并成一条时间轴；自动算冲突；置顶"现在最重要"的一件事。
2. **发现** — 按兴趣、学习到的偏好、截止紧迫度、来源可信度排序；每条推荐都给出**可解释的理由**（"你选了「科技」""报名今天截止"）。

**浅但真实**

3. **资料** — MTH / EAP 优先，按科目筛选，AI 总结 + 自测题，人工核对标记。
4. **社区** — 学长问答、找队友、兴趣群三个入口，支持发布（本地演示）。
5. **新生** — 7 天清单、FAQ、选课三步、校园系统入口。

## 现场演示（约 90 秒）

演示时钟固定在当天 11:00，保证每次演示的冲突和倒计时完全一致。

1. **今日**：08:30 作业已过期，09:00 微积分已结束，11:00 学术英语进行中；置顶卡片是"现在最重要"。
2. **发现**：讲推荐理由——不是"猜你喜欢"，是"你选了科技 + 报名今天截止"。
3. 点 **AI 产品设计工作坊** → **加入今日**。
4. 回到 **今日**：时间轴多出 14:00–16:00，顶部立刻出现红色统计和冲突提示：

   > 14:00–16:00「AI 产品设计工作坊」与 15:00–16:00「中国文化」重叠 60 分钟。

5. **资料**：打开 MTH009 笔记 → AI 总结 + 自测题（可查看答案）。
6. **发现 → 粘贴通知**：把公众号原文贴进去，AI 抽出时间/地点/截止/标签，确认后进活动库。

## 技术栈

- React 19 + Vite 8 + Tailwind CSS 4
- 图标 lucide-react
- 无路由、无状态库、无数据库、无登录——48 小时内能讲清楚的复杂度
- PWA：manifest + service worker，可安装到主屏，断网仍可打开
- Android：用 PWABuilder 打成签名 APK（TWA），配 `assetlinks.json` 后全屏运行
- 部署：Vercel（静态站 + `/api/chat` 服务端代理）

## AI 怎么接

默认 **mock**：不联网、不花钱、不断网也能完整演示。所有 AI 按钮都会返回模板结果，并标注"演示模式 · 模板生成"。

接真实模型（可选）：

1. 在 Vercel 项目里配置环境变量
   - `AIHUBMIX_API_KEY`（**只放服务端，不加 `VITE_` 前缀**）
   - `AIHUBMIX_BASE_URL`（默认 `https://aihubmix.com/v1`）
   - `AIHUBMIX_MODEL`（默认 `gpt-4o-mini`）
   - `VITE_USE_REAL_AI=true`（前端开关）
2. 前端只请求同域 `/api/chat`，key 不出服务器；任何失败都会静默回退 mock，不会把错误抛到界面上。

三种模式：`material`（资料总结+出题）、`reason`（把规则算出的理由改写成一句话）、`event`（粘贴通知解析）。

**推荐理由是代码算出来的，AI 只负责改写措辞**——模型不能凭空编造"因为你喜欢"。

## 真实与示例的边界

比赛规则要求作品在赛期内完成，且不得使用未授权的第三方内容。这个仓库里的处理：

- 所有活动、资料、帖子、匹配对象都是**虚构示例**，界面上逐条标注"示例"
- 活动来源写"官方邮件（示例）""学校官网（示例）"，不声称已对接真实公众号或邮箱
- 资料库不含任何真实往年题、老师课件或受版权保护的讲义
- 真人匹配只做**演示**：双方自愿、可随时关闭、有举报入口，演示资料为假名，不上传任何真实信息
- 页脚与详情页都写明"演示数据，非官方系统"
